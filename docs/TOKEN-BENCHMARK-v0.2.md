## 测量范围

使用本机 Codex CLI 0.160.0 的 `gpt-6.1-sol / ultra`，执行六组新任务；每组 A 由主模型直接搜索和读取，B 通过已安装 multi-ai skill 委派后核验。每臂都是新的短会话，禁用原生子 agent、插件、hook、网页和其他资料发现。两臂使用同一输出 schema、授权材料和验收问题，AB/BA 交替，最多两个独立任务同时执行。

B 的用量包含 skill 与参考说明、通路和依赖检查、提示准备、pack、delegate、交接读取、原文核验、反馈及必要恢复。失败和备援不剔除，不使用已有报告或 `--resume`。A 可自然使用 `rg`、局部读取，不强迫它全读后再比较。

材料均为虚构数据，不包含客户资料。两组调查、两组提取、两组复核。除一份 106,206 字节的长记录外，都是小材料。长记录包含 1,600 行背景和可定位的末尾决策，因此直接搜索是合理策略；它不代表必须通读的大型文档归纳。

## 用量口径

主模型用量来自实际 `codex exec --json` 的 `turn.completed.usage`，不是字符估算。总 token = input + output；cached input 是 input 的子集，reasoning output 是 output 的子集，均不重复相加。未缓存输入 = input − cached input，单列展示。

这测量的是上述 Codex CLI 对照，当前桌面聊天没有给出按任务的主模型 usage。本次结果不等于当前聊天的节省率、订阅额度节省率或费用变化。实验脚本编写、协调和独立评分的宿主开销没有单独计量，不混入 A/B 执行成本；B 自身的实际关键证据核验已计入。CLI 校准请求为输入 10,819、缓存输入 8,832、输出 8、7.631 秒，单列且不混入六组任务。即使主模型总 token 降低，外部模型用量及耗时仍需要一起考察。

每份最终答案核对固定事实、准确引文、已查范围和是否虚构测试；引用校验通过不能自动代替语义核验。完整且质量相当的配对使用 `1 − ΣB / ΣA`，不平均单组百分比。委派失败后主模型接手得到正确答案，仍记为委派失败。

官方计量说明：[Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode#make-output-machine-readable)。

## 限制

- 每题只有一次成对执行，六题是小样本。
- 新会话完整初始化的开销计入 B；熟悉工具、复用同一会话的工作流尚未测量。
- 本次短任务占多数，不能推导大型仓库调查、分布式长材料归纳的收益。
- 本轮测默认 Kimi/Grok CLI 委派，没有测显式 DeepSeek/GLM API 的主模型收益，也没有测 Claude 宿主的实际 token。
- 同一 provider 的缓存命中可能随顺序改变，已交替顺序并单列缓存，未进行费用加权。
- 未提供的外部 usage、实际模型请求数和宿主计量必须留空，不能当作零。

## 本轮暴露的问题

当前 B 每次初始化读取 skill 5,422 字符、delegation 参考 3,759 字符、完整 doctor 6,080 字符、完整 routes JSON 8,168 字符，合计 23,429 字符，尚未计入帮助、任务准备、产物和反馈。boundary A 只有三条读取命令、stdout 336 字符；B 有十六条命令、stdout 35,517 字符。交接很短也不能抵消此前及后续的工具输出和多轮上下文。

Kimi 在本轮调查启动约 2.3 秒后出现 `EMFILE: too many open files, watch`，工具表和 broker 尚未出现。已知是启动期文件监视失败，没有证据断言是登录失败、sandbox 故障或真的耗尽描述符。Grok 能读取同一份小快照，不支持将问题归于快照权限或清单。

Grok 的全局 native Read deny 误拦了本应允许的 `search_tool`，真实 stdout 返回 `Denied by permission policy: deny rule on read`。模型随后猜工具名称和参数，有些请求被 broker 严格 schema 拒绝。两次调查各出现三次发现拒绝；该缺陷增加了尝试，但不能证明它独自造成超时。代码位于 `src/delegate_cli.rs` 的受控 Grok 权限生成部分。

实际工具目录仍然受控，这里发现的是允许功能被误拒，不能称为隔离失效。修复需要同时确认发现成功、native Read 和 `use_tool.file/tool_input_file` canary 仍被拒绝，不能简单删除全局 deny。本实验未中途修改实现或安装版本，测到的是当前版本而非修复后的性能。

## 下一步判断

当前版本不宜每题自动委派。小搜索和可直接定位的材料留在主模型；不能仅凭材料字节数决定委派，查找几行决策与综合大量分散事实的成本不同。

优先修复 Kimi 启动兼容和 Grok 工具发现，再减少首次加载说明、全量诊断、帮助查询、报告枚举及反馈身份解析。让一条受管理命令返回短交接、明确 run/attempt 身份和必要状态，避免主模型为协调反复开工具回合。只在需要决策时再读取完整报告，核验关键原文证据仍保留。

修复后应新增必须综合大量内容的真实形状任务，并测同一熟悉会话的复用成本；不能把这轮负收益外推成委派必然无效，也不能用未经测量的优化宣称已经节省。
