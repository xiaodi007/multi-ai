# v0.2 验证记录（2026-10-04）

验收环境为当前 macOS Apple Silicon。只使用虚构仓库和材料，没有发送 Keel 业务资料。本地实现与发布包已备好不等于 GitHub 已发布；本轮不提交、推送或上传 release。

## 确定性验证

离线 Rust 测试覆盖旧 API、流式 UTF-8/SSE、退出/超时/重试、输出锁和恢复，以及新快照、MCP、委派、结构化结果、反馈和整组发布。API 委派测试清空环境并使用空 PATH，证明帮助之外的原生请求不依赖 Python、Node、uv 或 Cargo。

新增边界包括路径与符号链接逃逸、快照篡改、凭据/厂商配置排除、预算跨重连保存、严格备援、冲突零发送、缓存变化/损坏不复用，以及发布每一步故障后上一代 pointer 不变。CLI dummy 验证超时/取消退出进程组及认证目录的原子刷新、共享锁。

安装技能的 shell 测试覆盖全新安装、参数转发、用户修改保留、已知 v0.1 升级、合并说明、校验和保护和回退。具体测试数量与最终安装路径登记在本轮任务文件，避免重复维护易变计数。

## 真实厂商工具验收

Kimi 0.41.0 与 Grok 1.0.41（4220f3b224a6）使用实际客户端配合本地推理 mock：检查送入模型的实际工具表并强制尝试禁止工具。Kimi 仅有三个材料工具，Bash 调用被拒绝；Grok 仅有两个 MCP 元工具，native bash 与 use_tool 的本地 file/tool_input_file 输入被阻断，外部 canary 未被读取或修改。

真实联网调查在提示中隐藏答案，两家都通过内部读取服务找到虚构端口 7319 与 router.rs 的行号、哈希。修复认证刷新后 Kimi 连续两次非缓存调查成功，分别 10,406 ms 和 13,902 ms，每次 list/read 两次。Kimi 未提供 usage/内部请求数，保留 null。

修复版 Kimi 另完成 106,206 字节长材料提取：14,631 ms、4 次工具调用、累计返回 1,748 字节，交接 966 字符；正确找出最后三行的生效决策与未决超时，并明确前部材料仅做关键词搜索、没有全部阅读。这验证了默认 extract 通路的按需读取行为，没有把整个材料装入初始提示。

早期 Kimi 适配器使用单文件认证链接；厂商原子刷新可能替换链接，使轮换凭据随临时目录删除。随后原登录被厂商拒绝并写成空 token tombstone，日志不足以证明那次是否发生刷新，不能归因于自然过期。已改为 credentials 与 oauth 刷新锁目录共同桥接，四次顺序/并发 dummy 刷新均持久保存。独立设备登录已恢复并通过上述连续验收；原厂商登录的设备授权等待超时，仍需用户运行 `KIMI_CODE_HOME="$HOME/.kimi-code" kimi login` 完成新授权，不宣称已恢复。该状态在任务文件单独登记。

每组固定输入、任务和期望答案，主 AI 使用定向搜索/读取核对基线，再核验委派报告。反馈均为 agent，未标记 human。

历史保留早期三次 Kimi 认证失败和一次长材料错误行号，未删除失败以美化结果。错误行号被结构校验拒绝，未发布成功报告；API 加入物理行号后重新调用，正确引用第 1601–1603 行。

长材料 API 实际 usage 为输入 23,976、输出 424、总计 24,400 tokens；日志为 869，缓存身份复核为 1,129。Grok usage 按客户端原样保存，其内部请求数仍未知，客户端 costUSD 不当作账户账单。

宿主没有提供每个对照任务的实际 token、耗时与成本，这些字段均为 null。因此以上是正确性对照及委派端测量，尚不构成严格的 token 收益实验，不宣称节省百分比。短材料委派耗时与 CLI 上下文开销很大，简单搜索应留在宿主；长材料短交接减少待阅读字符，也仍需核验关键证据。

原始报告、反馈与指标保存于用户本地状态目录的 validation/v02-pairs-*，不会进入源码或发布包。下一轮若宿主可导出实际 token，再复用固定任务做完整成对测量。
